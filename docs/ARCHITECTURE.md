# Architecture
`src/core` owns host-independent models, media protocols, bounded state and scroll physics. `src/component` integrates foobar2000/Columns UI, UI, artwork, D3D renderers and worker lifecycles. `src/analysis-worker` performs contained background analysis; playback and real-time callbacks do not perform artwork/network/compilation work. The native CRT tool is also built from source.

`src/shader-render` builds the independent `goden-shader-render.exe` used only by Kerr-Newman Original and Music. It has no foobar2000 SDK dependency. Bounded value records cross the public IPC boundary; the renderer publishes only the final RGBA8 image through a keyed shared GPU texture on the same adapter. The player polls without waiting on its UI thread and owns the child through a private kill-on-close job. Hidden views suspend work, pause retains the four-second tail, and other effects do not launch this program. See [Kerr-Newman program boundary](KERR-RENDERER.md) for protocol, failure handling and reproduction. Resource measurements must include both programs and final-image transport, not only shader-pass timestamps.

Audio analysis is shared; visual envelopes/events belong to renderers. Album visuals retain fixed GPU constant-buffer contracts and existing quality/presentation limits. The host executable remains unchanged; a narrow Columns UI creation context establishes PMv2 and restores the thread context afterwards. Its existing host hook is called before the Columns fallback DPI handler.

Presence has independent RPC and cover lanes, latest-work cancellation, explicit provider/consent policy and content/version caching. The private relay source is optional infrastructure, not required for public Catbox operation. Production builds disable QA mutation/fault injection at compilation; QA builds require an explicit switch plus runtime profile authorization.

Database connections serialize initialization with bounded Windows mutex ownership keyed to the physical file handle supplied by SQLite's Windows VFS. Ownership covers WAL setup, schema-version reads, migration backups and commits; it is released before ordinary work. This prevents independent startup services/processes from migrating a stale version concurrently. A timed-out opener reports an error; an abandoned owner still requires normal SQLite recovery and complete migration.

Build-only dependencies include Python, PowerShell, Git, Node (relay/tests), GLSLang, SPIRV-Cross, FXC, CMake/Ninja and Inno Setup. None introduces a browser/Node/Python process into the shipped player.
