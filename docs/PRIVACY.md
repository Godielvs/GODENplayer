# Privacy and external services
The player stores library, playlists, analysis, preferences and artwork caches locally. No general project analytics or remote crash submission is added. Voluntary QA/diagnostic output may include local paths: inspect and sanitize it before sharing.

## Discord Presence
Text Presence uses local Discord IPC and sends track/artist/album/progress to Discord. It can be turned off independently. A configurable public Application ID is supplied; no Discord developer account is required. Public application IDs are identifiers, not credentials.

New public setup offers **Automatic** covers checked by default, with disclosure before the first request: Uguu temporary public uploads, Catbox persistent public uploads, and artist/album lookup through MusicBrainz / Cover Art Archive. ImgBB and private relay are excluded from this default. Direct component installation has no implicit consent: configure it in Options. Existing provider choices and allowlists are preserved. Disabling covers stops new cover jobs/uploads; disabling Presence stops its workers. Already transmitted network bytes cannot be recalled.

Only a newly encoded bounded square PNG thumbnail is uploaded (512 px maximum, lower bounded fallback encodings). Original EXIF, other image metadata, music bytes, filenames and local paths are not included. The external service still sees your IP. Anonymous Catbox API requests omit userhash; no account/key/project server is required. Catbox states anonymous uploads may remain until two years of inactivity. GODENplayer does not have an anonymous deletion capability, and turning off uploads does not delete previous objects. Availability/retention are outside this project's control. Do not upload artwork you are not entitled to share.

The durable local content/version cache stores the original Catbox URL immediately after upload. Current compatibility delivery additionally uses **wsrv.nl**, an independent image proxy, which receives that public URL. Before trusting an unverified URL, the worker checks both its original file and the delivery image; a proxy can otherwise conceal source truncation. Successful pairs use the in-memory fast path without per-track network verification. The local cache also stores a SHA-256 fingerprint of the exact validated delivery URL and complete PNG. After restart, the worker can reuse a byte-identical, fully checked CDN response even when the original host is temporarily unavailable. Acknowledged-only entries never gain this exemption, and changed CDN bytes require a healthy origin again. Transient delivery failures reuse the stored URL. An origin may be replaced only after a ten-minute guard and an explicit 404/410 response or a confirmed empty or structurally incomplete/corrupt PNG from Catbox itself. The latter requires a completed HTTP 200 body matching its declared length; timeouts, short transfers, HTML and unknown-length damage do not authorize another upload. Image checks accept at most 1 MiB within the existing deadline and validate complete PNG chunks and CRCs, rather than just the signature. Recovery uses lossless PNG filtering, preserves the thumbnail's pixels and dimensions, and records its progress locally so a restart does not cycle through rejected representations. There are at most four alternative encodings for a newly tracked image; older untracked entries get one conservative alternative. If none remain, covers fall back to text rather than lowering quality or repeatedly uploading broken bytes. Empty upload acknowledgements are failures and do not create a cache entry. Neither provider has a project-funded availability guarantee; rate limits or regional blocking may cause text-only fallback. For public covers, four ordinary resolve attempts use 1/5/30-second backoffs; at most two additional recovery attempts wait two and ten minutes, respectively, or longer if an origin-repair grace requires it. Metadata and Discord reconnection do not replenish that budget. Disabling covers, stopping or replacing the track cancels pending recovery. A single-provider choice never silently switches uploader. In Automatic mode, fallback is restricted to the explicitly enabled services described below. Each worker resolve visits those services a bounded number of times; a failed host has a short cooldown. The overall retry budget remains six resolves per cover key. Manual Try again starts a new bounded budget; Test cover additionally rechecks cached delivery. Neither button grants upload permission or applies unsaved Options changes.

### Additional cover providers

Options also offers the following explicit choices; existing Catbox/relay/disabled preferences are preserved. Changing provider or the Automatic allowlist requires renewed permission and Apply. New setup recommends Uguu, Catbox and catalogue; ImgBB and private relay require separate configuration. Legacy installer consent remains Catbox-only.

- **Uguu:** anonymous multipart upload of the same re-encoded miniature. Its published retention is 3 hours. GODENplayer treats links as valid for at most 175 minutes and renews shortly before that deadline during long playback, using new public uploads. Uguu's proxy representation requests a 2-hour cache lifetime. Actual uploads use a fresh, lossless PNG IDAT chunk layout, preserving every pixel and adding no image metadata, to avoid receiving an older deduplicated object with its original deletion time. Explicit duplicate acknowledgements do not grant a fresh lifetime. Turning covers off stops renewals but cannot recall previously delivered bytes.
- **ImgBB:** uploads use the user's own API key, not a shared project key. The key is sent only in the HTTPS POST body to `api.imgbb.com`, never in activity URLs or cache records. Windows DPAPI protects its persisted value for the current Windows user. A blank key field keeps the saved key. Public images have no requested expiration; disabling covers does not delete them. Revoke a key through the ImgBB account if needed.
- **Catalogue:** sends a tagged MusicBrainz release UUID, or artist and album, to MusicBrainz / Cover Art Archive. No local image or music is uploaded. Search accepts only an exact artist/album match and may still return a different edition's artwork. MusicBrainz queries identify GODENplayer and are limited to one per 1.1 seconds on the background worker. Positive and negative lookup caches are bounded and held in memory; a restart may repeat a query.
- **Automatic:** checks all enabled upload-provider caches before attempting uploads, then tries Uguu, Catbox, ImgBB and catalogue in that order. Unchecked services receive no new request through fallback. Catalogue lookup can be disabled independently. Private relay is never an implicit fallback from Automatic. Availability of one host does not guarantee another host or Discord's image proxy is reachable.

Public upload providers have separate persistent content/encoding caches; acknowledged URLs are saved before delivery checks complete. Expired temporary links are never extended by reading a cache entry. Catalogue and all public upload modes currently deliver through wsrv.nl, which is a shared external dependency. A successful local image check is not proof that another Discord client displayed it. No provider is selected based on a hidden shared project account, and no API keys are bundled.

A **custom private relay** is optional. Its endpoint and individual admission credential live in the local profile; Windows DPAPI protects the persisted credential for the current Windows user. Public defaults contain no personal relay. Session and image URLs are restricted to the configured HTTPS origin and WSS path. A private relay failure never falls back to public Catbox uploads. Relay URLs have short validity and the service requests thumbnails on demand; caches/network recipients can still retain a received image. Do not describe this as guaranteed deletion.

## Other access
Optional online lyrics sends title/artist/album/duration queries to LRCLIB. Offline lyrics mode disables that access. Presence may contain public MusicBrainz/Cover Art Archive links derived from metadata. Playing remote radio/HTTP media naturally contacts the selected media source through foobar2000. The optional statistics installer download contacts foobar2000.org; development preparation downloads pinned upstream tools and source. Windows/Discord/foobar2000 have their own privacy policies and settings.
